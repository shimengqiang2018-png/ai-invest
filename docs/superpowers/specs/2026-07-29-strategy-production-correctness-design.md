# 策略生产链路 Correctness 修复设计

## 1. 背景与目标

当前 RSRS 核心计算、默认 20 日固定截止日回测以及交易账本基础不变量已有自动化覆盖，但生产监控、行情获取、正式信号判定、滚动回测、审计指标和现金计息仍存在已确认缺陷。

本次目标是修复截至 2026-07-29 复核确认的全部 HIGH/MEDIUM 问题，使以下链路共享一致的数据和计算语义：

- 日常综合监控
- 动量信号扫描
- 网格趋势扫描
- 固定区间与滚动动量回测
- 量化审计
- 交易账本及现金收益

收益提升不是验收目标。验收只看 correctness、失败语义、可复现性和接口契约。

## 2. 设计决策

### 2.1 采用统一结构化核心

选择“统一结构化核心，CLI 只负责渲染”的方案。

- `strategy_monitor.py` 不再通过 shell 执行并解析 `momentum_signal.py` 和 `grid_trading.py` 的文本。
- 动量扫描、网格趋势和审计暴露可直接调用的 Python 函数，返回稳定的结构化对象。
- CLI 人类输出和 JSON 输出都由同一结构化对象渲染，避免同一数据扫描两次。
- 保持现有命令名称和主要参数兼容；`--json` stdout 必须是单一、严格 JSON 文档，诊断信息只能写 stderr。

未采用的方案：

- 最小正则补丁：改动小，但继续依赖脆弱文本协议、重复 I/O 和错误吞没。
- 外部服务化：当前是本地工具集，引入常驻服务、RPC 和部署生命周期没有必要。

### 2.2 单次冻结快照

一次监控执行内，每个 ETF 只加载一次行情，并形成带 manifest 的冻结快照。

- 动量展示、排名和操作建议必须消费同一份 4-ETF 快照。
- 正式排名要求所有池成员均成功、截止日期一致，且均为完成的交易日 bar。
- 任一池成员失败、日期不一致或数据质量不合格时，整体状态为 `unknown`，不得解释为“无信号”或触发清仓。
- 网格侧单个 ETF 失败只影响该 ETF，但必须标为 `unknown`，不得使用 `99` 等会落入正常分组的数值哨兵。

### 2.3 网络优先、合格缓存回退

用户选择网络优先策略。

- 每次默认先请求主源并执行交叉验证。
- 主源/备用源均失败时，可回退到通过 schema、hash、OHLC、复权和截止日校验的 v2 缓存。
- `as_of=None` 时，缓存回退必须覆盖当前期望的最近已完成交易日；不得无条件返回任意旧缓存。
- `as_of` 为周末或节假日时，允许最近一个不晚于 `as_of` 的交易日数据，不要求行情覆盖非交易日。
- transport 重试一旦成功，必须返回成功结果并清除旧错误；所有尝试失败后才抛最后一个错误。
- 单次请求和整池扫描都设 deadline；错误中保留 source、code、attempt 和是否使用缓存。

### 2.4 盘中信号只作 provisional

- 根据北京时间、交易日和最后一根 bar 日期判断是否完成收盘。
- 当日未完成 bar 可计算并展示指标，但 `formal=false`、`pass=false`、`provisional=true`，不得进入正式买入建议。
- 非当日的最新 bar 视为历史完成 bar；输出明确的数据日期。
- CLI 不提供绕过正式收盘判断的隐式默认值。测试可通过显式 clock/calendar 依赖注入构造时点。

## 3. 组件设计

### 3.1 行情层 `etf_market_data.py`

修复并补强：

- transport 成功重试返回值。
- 网络失败后的默认缓存回退。
- 非交易日 `as_of` 语义。
- 统一 deadline 和错误上下文。
- 缓存写入继续保持原子替换和完整校验。
- 冻结快照结构必须记录 source、adjustment、fetched_at、start/end、bar_count、content_hash 和 verification 元数据。

### 3.2 动量核心与扫描器

- `MomentumConfig` 明确区分 `rsrs_period` 与 `ma_period`；CLI 的 `--momentum` 仅表示 RSRS 周期，MA 默认保持 20，除非新增显式 `--ma-period`。
- 五条件只在共享核心实现一次：RSRS、MA、波动率、成交量和 RSI。
- 历史五日平均成交量为零或无有效基准时，成交量条件 fail-closed，不再返回 1.0 并放行。
- 扫描结果包含每只 ETF 的 code/name/date/source/formal/provisional/error 和完整条件结果。
- 人类输出直接遍历结构化结果，保留 ETF 标题、指标归属和信号分布。

### 3.3 综合监控器

- 移除 `shell=True`、重复调用和文本正则解析。
- 结构化区分 `buy`、`no_signal`、`provisional`、`unknown` 四类状态。
- 网格评分使用 `int | None`；失败时 `score=null` 且单独列入未知组。
- 风险指标从审计结构化结果或同一固定审计快照读取，禁止硬编码。
- 默认人类输出显示数据日期、来源、缓存状态、失败原因和审计截止日。
- `--json` 不打印横幅，使用严格 JSON 值；禁止 `Infinity`、`NaN` 等非标准值。
- Ctrl+C 必须及时传播并退出，不留下 shell 后代进程。

### 3.4 动量回测

- 信号日必须具备完整候选池横截面，否则该日不产生订单，并记录 `incomplete_cross_section`。
- rolling API 和 CLI 显式接收并严格消费 `end_date`。
- 所有 rolling 窗口复用一次预加载且按 `end_date` 截断的冻结快照。
- RSRS 与 MA 周期参数语义与生产扫描器一致。
- 现金收益在每个交易日 NAV 结算时按 `cash_return_rate / 252` 计入现金；配置为 0 时保持当前结果不变。
- 非零现金收益必须影响 NAV、绩效和基准对比，并在结果中记录实际累计金额。

### 3.5 交易账本

- 账本提供按交易日累计现金收益的单一入口，避免回测器自行改写现金。
- 计息发生在约定的每日 NAV 时点，确保同一天的交易和计息顺序固定且可测试。
- 默认 `cash_return_rate=0`，保持现有固定截止日回测数字兼容。

### 3.6 量化审计

- 压力情景只在实际回测区间内搜索；预热期不得进入候选场景。
- 删除把同一 `daily_nav` 两次计算后标成“日频 vs 双周”的伪对比。
- 审计结果提供稳定 JSON schema，监控器只消费该 schema。
- 风险指标的符号统一：报告展示 VaR/CVaR 为正的损失幅度，同时保留字段名说明，避免同一指标一处为负收益分位、一处为正损失值。
- 审计 `--end` 必须向所有行情和回测子流程传递。

### 3.7 网格回测和 CLI 契约

全部已确认问题包括网格侧：

- `grid_trading.py backtest --json` 只输出严格 JSON，不先打印人类报告。
- `profit_factor=∞` 在 JSON 中使用 `null`，并附状态字段说明无亏损交易。
- 非 JSON 模式保留当前可读报告。
- 网格 OHLC 双路径、止损后剩余期间估值、最低佣金和税费路径纳入回归测试并按账本统一执行。
- 生产配置、成交账本与账户快照一致性通过显式校验；不一致时 `table/status/trigger/risk/pnl` fail-closed，不生成委托建议。

## 4. 错误处理契约

所有结构化入口使用同一状态模型：

- `ok`：数据完整且计算成功。
- `provisional`：计算成功但最后一根 bar 未正式收盘。
- `unknown`：数据源、缓存、横截面或子计算失败。
- `no_signal`：数据完整且正式计算后没有标的通过。

约束：

- `unknown` 永远不能降级成 `no_signal`。
- 单标的错误必须包含 code、stage、source 和 message。
- CLI 结构化模式发生整体失败时返回非零退出码；仍可输出包含 `status=unknown` 的严格 JSON 错误对象。
- 人类输出明确标注未知状态，不给买卖动作。

## 5. 测试设计

每个缺陷先增加失败测试，再实现修复。

### 5.1 行情与信号

- 第一次 transport 失败、第二次成功时返回成功数据。
- 网络全失败时使用满足截止日的缓存；过旧或损坏缓存拒绝。
- 周末 `as_of` 使用最近交易日。
- 零历史成交量基准 fail-closed。
- 盘中当日 bar 只能产生 provisional 结果。
- 4-ETF 任一失败时禁止正式排名。
- 非默认 RSRS 周期下扫描器与回测器仍共享 MA20，显式 MA 参数时双方一致。

### 5.2 监控和 CLI

- 动量加载函数一次执行只调用一次行情快照。
- 正评分保持真实值，不出现 99。
- ETF 标题和信号分布完整输出。
- `unknown` 不产生“持币/换仓”建议。
- 监控风险值与审计结果逐字段一致。
- `strategy_monitor.py --json` 与 `grid_trading.py backtest --json` 可直接由严格解析器读取。
- 模拟 Ctrl+C 时及时退出且无子进程残留。

### 5.3 回测、账本与审计

- 缺横截面日不创建订单。
- rolling `--end` 后无窗口和行情越界。
- `cash_return_rate=0` 保持既有结果。
- `cash_return_rate>0` 按交易日/252累计，长期持币 NAV 符合公式。
- 压力场景不早于回测有效起点。
- 审计不再输出伪日频/双周对比。
- 网格最低佣金、税费、OHLC 歧义和止损后估值均有行为测试。

## 6. 验收标准

1. 全量自动化测试通过，现有测试不得减少。
2. 每个已确认缺陷至少有一个可失败的回归测试。
3. 4-ETF 固定截止日、现金收益率 0 的回测结果保持当前基线，除非修复本身明确改变错误行为；任何变化必须逐项解释。
4. `strategy_monitor.py --json`、`momentum_signal.py --json`、`grid_trading.py backtest --json` 和 `strategy_audit.py --json` 均可由严格 JSON 解析器直接读取。
5. 离线夹具下端到端监控在一次冻结快照上完成，不访问网络，不重复扫描。
6. 网络失败、盘中运行、缺横截面时均不生成正式买卖建议。
7. 固定截止日审计指标与监控展示一致。
8. 更新策略文档中的生产门禁、命令语义和修复后数据；未重新生成的数据保留“待重跑”标记。

## 7. 实施边界

- 不改变策略选池和五条件阈值。
- 不以提高历史收益为目标，不调参寻优。
- 不引入数据库、外部服务或新的全局依赖。
- 不执行真实交易、不修改券商条件单。
- 不提交、不推送，除非用户另行明确要求。
